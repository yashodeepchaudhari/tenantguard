The 5 Layers of Isolation (not just a rate limit)

LayerMechanismStops
L1 RequestToken buckets: rps, concurrency, bandwidthRequest floods
L2 CostCPU-ms / memory budgets charged after each job"Few but heavy" requests
L3 SchedulerWeighted fair queue + per-tenant bulkheadQueue hogging, line cutting
L4 KernelDocker cgroups (cpus, memory, pids) + penalty-box containerCPU bombs, memory hogs
L5 DataPostgres RLS + per-tenant connection pool + query timeoutDB floods, data leaks

Adaptive Throttling Levels

LevelTriggerAction
L0 Normalscore < 1.5Full rate, can borrow idle capacity
L1 Warnscore ≥ 1.5 for 5 sEvent logged, dashboard alert
L2 Throttlescore ≥ 2AIMD: rate × 0.5 each tick
L3 Deprioritizestill highScheduler weight reduced to 0.25
L4 Quarantinescore ≥ 4 or memory-limit hitsJobs routed to the penalty-box container
Recoveryscore < 1 for 15 s+10% per tick, step down one level
noisy_score[t] = max_r( share[t,r] / fair_share[t] ) × (1 + victim_impact)  (+ spike bonus if z > 3)
  → a tenant is flagged ONLY if it over-uses AND other tenants are actually suffering

A Request's Journey, Step by Step

 ┌─────────────────────────────────────────────────────────────┐
 │  STEP 1 - TENANT SENDS A REQUEST                            │
 │  "Hi, I'm Tenant A (key: abc123). Please do this work."     │
 └──────────────────────────┬──────────────────────────────────┘
                            ▼
 ┌─────────────────────────────────────────────────────────────┐
 │  STEP 2 - GATEWAY  (Security Guard)                         │
 │  • Who are you?            → checks API key                 │
 │  • Do you have quota left? → checks your limits in Redis    │
 │        YES → go ahead                                       │
 │        NO  → "429: Slow down!"                              │
 └──────────────────────────┬──────────────────────────────────┘
                            ▼
 ┌─────────────────────────────────────────────────────────────┐
 │  STEP 3 - SCHEDULER  (Fair Queue)                           │
 │  Every tenant has their own line:                           │
 │     A: ■ ■           B: ■           C: ■ ■ ■                │
 │     X: ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■  (attacker spamming)         │
 │  Serve one from each line in turn → X can't cut the line    │
 └──────────────────────────┬──────────────────────────────────┘
                            ▼
 ┌─────────────────────────────────────────────────────────────┐
 │  STEP 4 - WORKER  (does the actual job)                     │
 │  Runs inside a Docker container with a hard limit:          │
 │     "max 1 CPU, max 512 MB RAM"                             │
 │  While working, it measures: CPU used, memory used, time    │
 │  Bad tenants go to the small "Penalty Box" container        │
 └──────────────────────────┬──────────────────────────────────┘
                            ▼
 ┌─────────────────────────────────────────────────────────────┐
 │  STEP 5 - DATABASE                                          │
 │  Each tenant sees ONLY their own data                       │
 │  Each tenant gets limited connections + query time          │
 └──────────────────────────┬──────────────────────────────────┘
                            ▼
                   Response back to tenant

        ┌───────────────────────────┐

        │ How fast are responses?   │
        └─────────────┬─────────────┘
                      ▼
        ┌───────────────────────────┐

        │ Is someone using way more │

              no ◄────┴────► yes
              │              ▼
              │   ┌───────────────────────────┐
